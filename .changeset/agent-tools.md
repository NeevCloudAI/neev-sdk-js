Agent tools: `@neevcloud/sdk/agent-tools` exports `SandboxTools`, `DESCRIPTIONS` and `PARAMETERS`, the NeevCloud sandbox tool contract for agents built on any framework. `new SandboxTools(sandbox, { allowPreview, allowRollback, allowProcesses })` binds `runCommand`, `writeFile` and `readFile`, plus the opt-in `exposePort`, `checkpoint`/`rollback`, and `startProcess`/`readProcessOutput`/`stopProcess`; `names()` lists the enabled tools in contract order, and `call(name, args)` runs a model's tool call by name. Each tool takes the model's snake_case arguments and resolves to a plain result, with `{ error }` for failures the model can fix, including an unknown tool or missing or malformed arguments. `readProcessOutput` takes an optional `wait_s` (0–60 s) to wait for a running process to exit before reading. `DESCRIPTIONS` and `PARAMETERS` (JSON Schema per tool) match the Python SDK's exactly. `runCommand` turns the network edge's 524, for a command silent for about 2 minutes, into an error result that points the model at `start_process`. Argument and result types are exported for every tool.

An `exec` with a `timeoutMs` longer than the client's `timeoutMs`, and a blocking `processes.get(id, { wait: true })`, no longer fail with `APITimeoutError` at the client timeout: the sandbox starts those responses only when the command ends or the process exits, so their per-request timeout now extends by the exec's `timeoutMs` and by the sandbox's 5-minute wait ceiling. The network edge in front of the sandbox still cuts off a response that stays silent for about 2 minutes, so long quiet work belongs in `sandbox.processes`.
